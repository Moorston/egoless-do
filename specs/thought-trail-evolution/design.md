## 1. 背景与目标

### 1.1 现状分析

当前系统已有基础的感念和脉络功能：

```
┌─────────────────────────────────────────────────────────────────┐
│                      当前数据模型                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   MindReflection (感念)                                         │
│   ┌──────────────────────────────────────┐                      │
│   │ id, content, tags[], mood            │                      │
│   │ timestamp, colors, isPinned          │                      │
│   │ linkedPlanItemId? (关联计划任务)       │                      │
│   │ thoughtTrailIds?[] (所属脉络)         │                      │
│   └──────────────────────────────────────┘                      │
│                    │                                            │
│                    │ 1:N (有序)                                 │
│                    ▼                                            │
│   ThoughtTrail (思路脉络)                                       │
│   ┌──────────────────────────────────────┐                      │
│   │ id, name, description?               │                      │
│   │ reflectionIds[] (有序)               │                      │
│   └──────────────────────────────────────┘                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**现有功能**：
- 基础的感念记录（内容、标签、心情、颜色）
- 思路脉络创建（手动选择感念）
- 时间线展示（简单的时间排序）
- 标签脉络（按标签聚合）

**现有局限**：
- 脉络只有顺序，没有语义连接
- 没有自动发现机制
- 缺乏复盘分析功能
- 与习惯/计划/打卡系统联动弱

### 1.2 目标定位

从「记录工具」演进为「思维伙伴」：

```
┌─────────────────────────────────────────────────────────────────┐
│                      角色转变                                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  当前：记录工具                                                  │
│  用户记录 → 系统存储 → 用户回顾                                  │
│  价值：保存记忆                                                  │
│                                                                 │
│  目标：思维伙伴                                                  │
│  用户记录 → 系统分析 → 洞察反馈 → 行动指导 → 用户行动            │
│       ▲                                              │          │
│       └──────────────────────────────────────────────┘          │
│  价值：促进成长                                                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 核心价值主张

1. **看见自己** — 帮助用户发现思维模式和盲点
2. **理解自己** — 理解情绪和行为背后的原因
3. **指导行动** — 将洞察转化为可执行的方案
4. **持续成长** — 形成思考-行动-反馈的闭环

## 2. 核心设计理念

### 2.1 复盘的心理动因

什么会让人产生「回顾过去」的冲动：

1. **发现变化** — "我居然是这样走过来的"（意外感、惊喜）
2. **看见模式** — "原来我一直在重复这个循环"（自我觉察）
3. **确认成长** — "我现在比那时候强多了"（成就感、信心）
4. **理解自己** — "原来我当时是这样想的"（自我接纳）
5. **获得力量** — "那次那么难都过来了"（韧性、勇气）

**设计启示**：不是「展示数据」，而是「讲述故事」

### 2.2 复盘的三个层次

```
┌─────────────────────────────────────────────────────────────────┐
│                      复盘金字塔                                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│                       ┌─────────────┐                           │
│                       │   转化层    │  将洞察变成行动             │
│                       │  Transform  │                           │
│                       └──────┬──────┘                           │
│                              │                                  │
│                  ┌───────────┴───────────┐                      │
│                  │       理解层          │  发现模式和原因        │
│                  │     Understand        │                      │
│                  └───────────┬───────────┘                      │
│                              │                                  │
│          ┌───────────────────┴───────────────────┐              │
│          │             记录层                    │  描述发生了什么│
│          │             Record                    │              │
│          └───────────────────────────────────────┘              │
│                                                                 │
│  大多数app停留在记录层                                           │
│  我们要帮助用户到达理解层和转化层                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 设计原则

1. **故事性 > 列表性** — 用叙事方式展示脉络，不是平铺列表
2. **连接有语义** — 每条连接都有故事（引发、演进、转折、确认）
3. **情绪可视化** — 一眼看到「心路」变化
4. **时间有呼吸感** — 密集思考期紧凑，沉默期留白
5. **渐进式披露** — 默认简单，复杂功能按需展开
6. **自动 > 手动** — 系统能做的不让用户做
7. **轻量交互** — 连接感念：1次点击 + 1次选择

## 3. 数据模型设计

### 3.1 核心概念：意图 Intent

**为什么需要「意图」**：
- 感念是「想法」，但想法如何变成「行动」？
- 计划是「任务」，但任务背后的「为什么」是什么？
- 习惯是「行为」，但行为背后的「动机」是什么？

意图是连接「思考」和「行动」的桥梁。

### 3.2 完整数据模型

```
┌─────────────────────────────────────────────────────────────────┐
│                      数据关系图                                  │
├─────────────────────────────────────────────────────────────────┤

│  │  id, content, tags[], mood, timestamp                   │   │
│  │  thoughtTrailIds[]      // 所属脉络                      │   │
│  │  intentId?: string      // 触发的意图                    │   │
│  │  checkinId?: string     // 关联的打卡                    │   │
│  └─────────────────────────────────────────────────────────┘   │
│           │                                                     │
│           │ N:1                                                 │
│           ▼                                                     │
│  ThoughtTrail (脉络)                                            │
│  ┌─────────────────────────────────────────────────────────┐   │

│  │  reflectionIds[]        // 有序感念列表                  │   │

│  │  outcome?, learnings?[]                                 │   │

│           │                     │                               │
│           │ 1:N                 │ 1:N                           │

│  ┌─────────────┐       ┌─────────────┐                         │
```

### 3.3 Intent 状态流转

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│  种子   │───▶│  成长   │───▶│  活跃   │───▶│  达成   │
│  seed   │    │ growing │    │ active  │    │achieved │
└─────────┘    └─────────┘    └─────────┘    └─────────┘
     │              │              │              │
     │              │              │              ▼
     │              │              │        ┌─────────┐
     │              │              │        │  融入   │
     │              │              │        │integrated│
     │              │              │        └─────────┘
     │              │              │
     ▼              ▼              ▼
┌─────────┐   ┌─────────┐   ┌─────────┐
│  放弃   │   │  放弃   │   │  放弃   │
│abandoned│   │abandoned│   │abandoned│
└─────────┘   └─────────┘   └─────────┘
```

### 3.4 连接类型 LinkType

```typescript
type LinkType = 
  | 'inspire'   // 引发/启发
  | 'evolve'    // 演进/深化
  | 'contrast'  // 对比/转折
  | 'respond'   // 回应/反思
  | 'related'   // 相关/类似
```

### 3.5 意图来源 IntentSource

```typescript
type IntentSource = 
  | 'reflection'   // 从感念中提炼
  | 'review'       // 从复盘中发现
  | 'insight'      // 从洞察中产生
  | 'external'     // 外部触发（阅读、对话等）
```

### 3.6 ReflectionLink 完整类型

```typescript
interface ReflectionLink extends Syncable {
  id: string;
  fromId: string;        // 起点感念 ID
  toId: string;          // 终点感念 ID
  type: LinkType;        // 连接类型
  note?: string;         // 用户备注
  createdAt: number;
}
```

## 7. AI辅助设计

### 7.1 AI的角色定位

**不是**：
- ✗ 替用户思考
- ✗ 给出标准答案
- ✗ 评判用户
- ✗ 过度打扰

**而是**：
- ✓ 帮助用户看见盲点
- ✓ 发现用户自己没注意到的模式
- ✓ 引导用户深入思考
- ✓ 在关键时刻提供视角
- ✓ 降低记录和反思的门槛

### 7.2 AI应用场景

#### 7.2.1 感念捕捉时

1. **智能标签建议** — 基于内容分析推荐标签
2. **情绪识别与深化** — 帮助用户更精确地识别情绪
3. **内容扩展引导** — 简短内容时引导深入

#### 7.2.2 脉络构建时

1. **自动脉络发现** — 基于语义相似度、时间聚类、情绪轨迹
2. **脉络洞察生成** — 分析转折点、应对策略、延伸思考

#### 7.2.3 意图与行动时

1. **意图提炼** — 从脉络中提炼可能的意图
2. **计划生成** — 基于用户历史数据设计计划
3. **风险预警** — 基于历史习惯养成数据预测风险

#### 7.2.4 复盘时

1. **引导式对话** — 像智慧的朋友在对话
2. **深度提问** — 基于用户数据问好问题

#### 7.2.5 日常使用

1. **情境感知提醒** — 基于情境的智能提醒
2. **打卡时洞察** — 即时反馈和鼓励

### 7.3 AI技术架构

```
┌─────────────────────────────────────────────────────────────────┐
│  Layer 1: 本地轻量级AI                                           │
│  • 关键词提取、情绪词典匹配、标签建议、时间模式分析、简单统计     │
│  • 技术：规则引擎 + 本地词典 + 统计分析                          │
│  • 特点：零延迟、零成本、完全离线                                 │
├─────────────────────────────────────────────────────────────────┤
│  Layer 2: 本地小型模型（可选）                                    │
│  • 语义相似度、内容分类、情感分析、实体提取                       │
│  • 技术：小型embedding模型（如MiniLM）                           │
│  • 特点：低延迟、低资源消耗、离线可用                             │
├─────────────────────────────────────────────────────────────────┤
│  Layer 3: 云端大模型（用户授权）                                  │
│  • 深度洞察、对话式复盘、复杂模式识别、个性化建议                 │
│  • 技术：调用大模型API                                           │
│  • 特点：能力强、需要网络、需要用户授权                           │
│  • 注意：数据最小化、不上传原文、只上传摘要                       │
└─────────────────────────────────────────────────────────────────┘
```

### 7.4 AI的边界与克制

1. 用户可以完全不用AI — 所有AI功能都是可选的
2. AI建议可以忽略 — 每个建议都有「忽略」选项
3. AI不会评判 — 用中性的语言，不说「你应该」
4. AI不会过度打扰 — 提醒频率有上限
5. 隐私是底线 — 默认离线处理，云端需要授权

## 9. 风险分析与兼容性

### 9.1 数据模型变更影响

| 改动 | 影响范围 | 风险等级 | 说明 |
|------|----------|----------|------|
| ThoughtTrail 新增字段 `source`, `intentId`, `insightSummary` | 同步、存储 | ⚠️ 中 | 新增可选字段，向下兼容，但需要处理旧数据为 undefined 的情况 |
| MindReflection 新增字段 `intentId`, `checkinId` | 同步、存储 | ⚠️ 中 | 同上，新增可选字段 |

### 9.4 高风险点详细分析

#### 🔴 高风险 1：打卡流程改造

```
现有打卡流程：
用户点击打卡 → 保存打卡记录 → 完成

改造后流程：
用户点击打卡 → 保存打卡记录 → 显示心情选择 → 可选输入想法
            → 选择是否保存为感念 → 完成

风险点：
1. 打卡是高频操作，任何卡顿都会被感知
2. 如果弹窗逻辑出错，可能导致打卡失败
3. 新增的字段如果处理不当，可能影响同步

建议：
• 保持原有打卡逻辑不变
• 新增功能作为可选步骤，可以跳过
• 心情和想法的保存使用独立的 API，失败不影响打卡
```

#### 🔴 高风险 2：同步逻辑

```
现有同步：
12 个实体类型，已有完整的同步逻辑

新增同步：
Intent、ReflectionLink 两个新实体

风险点：
1. 新实体的同步逻辑如果出错，可能导致数据丢失
2. ThoughtTrail 新增字段如果同步处理不当，可能覆盖旧数据
3. 旧版本 app 无法识别新字段，可能导致兼容问题

建议：
• 新增实体使用独立的同步集合
• 新增字段使用可选类型，旧数据自动兼容
• 充分测试双向同步场景
```

#### 🔴 高风险 3：数据迁移

```
现有数据：
用户已有 ThoughtTrail、MindReflection 等数据

迁移需求：
1. 旧 ThoughtTrail 缺少 source 字段 → 需要默认值
2. 旧 MindReflection 缺少 intentId → 自动为 undefined
3. 旧 Checkin 缺少新字段 → 自动为 undefined

风险点：
1. 如果迁移逻辑出错，可能导致旧数据损坏
2. 如果不迁移，新功能可能无法正确处理旧数据

建议：
• 新增字段全部使用可选类型（?）
• 代码中统一使用 `??` 或 `||` 处理 undefined
• 不需要专门的迁移脚本，运行时兼容即可
```

1. **新手引导** — 如何让新用户理解脉络和意图的价值

   - 用户可手动归档或关闭意图
4. **AI建议的频率** — 如何平衡有用和打扰
5. **自动 vs 手动** — 哪些该自动，哪些该手动
6. **隐私边界** — 哪些数据可以用于AI分析

### 10.8 边界情况处理

| 情况 | 处理方式 |
|------|----------|
| **自动脉络重复** | 通过标签+时间窗口去重，已存在的不重复创建 |
| **感念从脉络移除** | 同时清理关联的 ReflectionLink |
| **意图放弃** | 提示用户是否保留关联的计划/习惯 |
| **大量感念** | 分页加载，后台异步分析 |
| **单条感念无法形成脉络** | 至少需要 2 条感念才能创建脉络 |
| **跨月/跨年的脉络** | 日期范围显示格式：「6/1 ~ 7/5」或「2025/12/30 ~ 2026/1/5」 |
| **重复运行自动发现** | 检查是否已存在相同标签+时间窗口的脉络，已存在则跳过 |
| **1000+ 感念的性能** | 使用虚拟列表渲染，分析任务放到后台线程 |
| **网络不稳定时的同步** | 本地优先，后台队列同步，失败后重试 |
| **多设备同时编辑** | 以最后更新时间为准，冲突时保留最新版本 |
| **复盘用户跳过步骤** | 记录已填写的部分，下次可继续 |
| **AI 调用失败** | 显示降级文案，不影响核心功能 |
