## Schema 快照对比（验证 B）— 降级声明

### 降级原因
按 design.md 预先批准的退路："如果 export_schema.mjs 因 SQLite 驱动依赖
RN 运行时无法在 Node 跑，降级为验证 A 为主"。

已尝试 3 种 schema 快照方法，均不可行：
1. **better-sqlite3**：全局安装但 NODE_MODULE_VERSION 不兼容（127 vs 147）
2. **sqlite3 CLI**：无法复现 migrateDatabase 的条件迁移逻辑
   （PRAGMA table_info 检查列存在性 → 不存在才 ALTER）；
   无脑执行全部 SQL 会报 "duplicate column name"、"no such column: dur"、
   "cannot rollback - no transaction is active" 等错误
3. **expo-sqlite**：依赖 React Native 运行时，无法在 Node 直接调用

### 降级后的验证策略
**以验证 A（代码层 diff 逐行审查）为充分证明**：

move-only 重构的本质——函数体逐字节搬入命名函数，调用处替换为
`await migrateXxx(db)`。如果 git diff 确认：
1. 每个提取的函数体与原位置代码逐字节一致（无字符修改）
2. 调用处顺序与原迁移块顺序一致
3. tryAddCol / CREATE TABLE / for 循环未被改动
4. 事务边界（BEGIN TRANSACTION...COMMIT + try-catch ROLLBACK）随函数体搬移

那么运行时行为必然完全相同——相同的 SQL 语句以相同的顺序、相同的
条件执行。schema 快照对比作为补充验证退化为可选。
