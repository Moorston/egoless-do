## Context

感念页（ReflectionsScreen）目前存在几个交互问题：
- 左滑手势与长按菜单功能重叠（编辑、创建任务），增加用户认知负担
- 置顶功能使用率低但占用 UI 空间（卡片徽章、详情页按钮、筛选条件）
- 时间范围筛选的底层逻辑已就绪（`dateRange` in `ReflectionFilters`），但缺少 UI 入口
- 历史感念全部平铺展示，当数据量大时浏览体验差

## Goals / Non-Goals

**Goals:**
- 移除置顶功能的所有 UI 入口（卡片徽章、详情页按钮、筛选条件）
- 移除左滑手势，统一为长按菜单操作
- 详情页增加创建任务/解绑任务按钮（复用长按菜单的逻辑）
- FilterDrawer 增加日期范围筛选 UI（快捷预设）
- 旧日期组折叠为摘要卡片，仅展开最近一天

**Non-Goals:**
- 不修改 Web 端
- 不从类型定义中删除 `isPinned` 字段（保持向后兼容）
- 不修改统计页
- 不引入新的外部依赖

## Decisions

### 1. 日期范围筛选：快捷预设 vs 自定义日期选择器

**选择：快捷预设按钮**

在 FilterDrawer 中提供 4 个预设按钮：本周、本月、近7天、近30天。点击即应用，再次点击取消。

**理由：**
- 自定义日期选择器需要引入额外依赖（如 `@react-native-community/datetimepicker`）
- 预设覆盖最常见的使用场景
- 交互简单，一个点击即可应用
- 底层 `dateRange` 已支持任意范围，未来可扩展

### 2. 移除左滑手势 vs 保留

**选择：完全移除 Swipeable**

从 ReflectionsScreen 内联卡片和 ReflectionCard 组件中移除 `Swipeable` 包装。长按菜单已提供编辑、创建/解绑任务、分享、删除等全部操作。

**理由：**
- 左滑与长按菜单功能重叠
- 移除后减少手势冲突
- 简化组件结构

### 3. 详情页按钮布局

**选择：替换置顶按钮为创建任务/解绑任务**

详情页底部操作按钮行：编辑 | 分享 | 创建任务/解绑任务 | 删除（仅当天）

复用长按菜单中已有的创建/解绑逻辑：
- 未关联时显示"创建任务"，点击打开创建计划任务弹窗
- 已关联时显示"解绑任务"，点击弹出确认后解绑

**理由：**
- 详情页是用户查看感念详情的主要场景，在此处提供任务关联操作更自然
- 复用已有的 `handleCreatePlanItem` 和 `unlinkReflectionFromPlanItem` 逻辑

### 4. 旧日期折叠策略

**选择：比较日期字符串，仅展开最近一天**

`groupReflectionsByDate` 返回的 key 是中文 locale 日期（如"6月5日 周四"）。通过比较原始 timestamp 判断哪个日期组是最新的，仅该组展开，其余折叠。

折叠状态的摘要卡片显示：
- 日期标题 + 感念数量
- Top 3 标签（最多显示 3 个）
- 主要心情（出现最多的心情）

点击摘要卡片可展开/收起该日期组。

**理由：**
- 不改变 `groupReflectionsByDate` 的返回格式
- 折叠状态用 `useState<Set<string>>` 管理（key 为日期字符串）
- 默认折叠旧日期，展开最近一天

## Risks / Trade-offs

- **[风险] 日期折叠的"最近一天"判断**：如果用户当天没有感念，最近一天可能是昨天。需要取 `byDay` 的第一个 key（已按时间降序排列）作为展开目标。
  → 缓解：`Object.entries(byDay)` 已按 timestamp 降序排列，第一组即为最近一天。

- **[风险] 快捷预设的时区问题**：本周/本月的起始时间需用本地时区计算。
  → 缓解：使用 `new Date()` 的本地方法（`getDay()`, `getDate()`）计算，不依赖 UTC。
