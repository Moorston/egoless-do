一、项目概览

egoless-do 是一个以 离线优先、隐私优先、零月费 为核心理念的多端应用，帮助用户养成健康饮食、规律冥想、运动等习惯，并捕捉内心感悟（感念脉络 / 思维 Trail）。技术形态为 Turborepo + pnpm workspace 单仓多包（monorepo），主力交付形态是 React Native + Expo 移动端，Web PWA 已归档。

其架构宪法（AGENTS.md）定义了三条不可妥协的底线：P1 Core 是 Sole Source of Truth；P2 Apps 是薄壳；P3 单向依赖 app → core。下文将逐一核验这些原则在真实代码中的落地程度。

三、数据流转

统一以本地 SQLite 为持久层，内存态与远程态通过同步引擎桥接：

  1. Zustand Store（内存）：30+ 个 slice，状态扁平挂载，业务状态以 core 的 slice factory 为唯一真源。
  2. StorageAdapter → WriteBatcher → SQLite（expo-sqlite）：persistChange() 实体数据（100ms 防抖批量写入），persistSettings() 直写 app_state 表，transaction() 跨 slice 原子操作，已取消 AsyncStorage 双轨。
  3. SyncService → PocketBase（远程）：定期同步 + SSE 实时推送 + LWW 冲突解决，零数据丢失保证。

四、同步架构

同步协议定义位于 packages/core/src/sync/（entitySchemas.ts 约 1188 行，conflict.ts、merge.ts、entities.ts），服务端 hook 在 backend/pb_hooks/。客户端 SyncEngine（位于 app 层）维护本地 syncQueue，推送按 50/批（最多 10 批）drain，拉取支持按实体分页与字段级增量（changedFields）以缩减负载。

19 个同步实体（部分）：habits、reflections、fasting_sessions、food_entries、checkin_records、meditation_history、exercise_entries、plans、plan_items、thought_trails、trail_notes、reflection_links、ai_configs 等。

冲突规则：LWW（Last-Writer-Wins）——未删除按时间戳大者胜（平局服务端胜），已删除按时间戳大者胜（平局删除方胜）；安全层为 JWT + epoch 踢出 + 输入校验。

五、宪法符合性评估

宪法原则状态说明
packages/core = Sole Source of Truth（类型 / 常量 / 纯函数） 部分符合 纯逻辑与类型基本落在 core；但大型 Engine 类实际位于 app 层，P1 精神被削弱
apps/ = 薄壳 不符合 移动端（71.7k 行）比 core（32.7k 行）更大，承载大量引擎 / 业务逻辑
单向依赖 app → core 符合 已验证 core 无反向 import apps/_archive；纯函数（streak/checkin）从 core 复用，无重复实现
feature-A → feature-B 组件禁止 违反 exercise → music / meditation 共 5 处越界 import（见风险清单 #3）
backend = PocketBase 唯一数据源 符合 结构正确；但 schema 导出缺 users auth 集合（见 #6）
同步协议在 core/sync 符合 协议定义与 server hook 分层正确、单一来源
宪法文档准确性 不符合 行数表过期且与自身"重构已完成"段落自相矛盾；_archive 路径写错（见 #1）

六、关键风险与技术债

#1 宪法文档与真实代码严重脱节（最高优先级）
  • AGENTS.md 中"当前问题文件"表格列出的旧行数（SyncEngine 1284 / SleepEngine 1001 / BreathingEngine 940 / HomeScreen 880 / RelationMapView 871），与其"重构已完成"段落给出的新行数（如 SyncEngine "1284 → 398"）相互矛盾，且两套数字均不等于真实值（884 / 342 / 464 / 838 / 450）。
  • 宪法把 _archive/ 写到了 apps/ 下，但磁盘上它在仓库根目录，全仓无任何引用指向 apps/_archive。
  • 结论：宪法作为"实时规范"已失效，需重新校准或标注为历史快照。
#2 引擎类在 app 而非 core，P1 形同虚设
  • 被宪法点名的 5 个超大文件全部位于 apps/mobile/：SyncEngine(884)、SleepEngine(342)、BreathingEngine(464)、HomeScreen(838)、RelationMapView(450)。
  • SyncEngine 884 行远超宪法自定的 600 行上限，也高于其声称的"398"。
  • 这与"core = Sole Source of Truth"的核心定位冲突，属于已承认但未解决的债务。
#3 跨 feature 的非法 import（明确违反 §2.2）
  • features/exercise/hooks/useExerciseAudio.ts:6 → ../../music/services/AudioSessionManager（exercise → music）
  • features/exercise/layouts/{EnduranceActive,GpsActive,MeditativeActive,StrengthActive}.tsx:7 → ../../meditation/MeditationMusicBar（exercise → meditation ×4）
  • 应提取至 components/ 共享层以消除紧耦合。
#4 core 大文件测试覆盖不均
  • core 共 54 个测试文件（整体不错），但多个大体积纯逻辑文件无测试：trail-creation.ts(693)、reflectionGraph.ts(468)、reflectionAnalytics.ts(303) 以及 precepts.ts、sleep.ts、zhiguan*.ts 等。
  • 最高流量逻辑（Trail 创建、感念图谱）恰是最缺测试的部分，违背宪法 P5「测试先行于复杂逻辑」。
#5 文件体积红线基本未被强制执行
  • app 层 14+ 个文件超 600 行宪法软上限，最大为 db/schema.ts(1203)、plan/PlanDetailContent.tsx(976)、reflections/QuickCreateTrailScreen.tsx(972)。
  • core/sync/entitySchemas.ts(1188) 为生成/派生单体，正确位于 core，但是合并风险热点。
#6 PocketBase schema 缺 users 认证集合
  • pb_schema.json 含 41 个 base 集合、0 个 auth 集合；若 users 为意图中的认证源，则导出不完整，或依赖 PocketBase 隐式 superusers——应明确记录。
#7 导航层绕过集中路由表
  • navigation/index.tsx:24,30 直接 import useSync / isDeviceSyncedBefore 自 ../features/sync/...，偏离 §2.2 建议的集中路由表模式。

七、改进建议（按优先级）

  1. 先修宪法本身：重新扫描真实行数并同步到 AGENTS.md；修正 _archive 路径；将"当前状态"与"重构完成"两节合并为单一可信来源。可脚本化（如 cloc）每次 PR 自动更新。
  2. 消除 5 处跨 feature import：将 MeditationMusicBar 与 AudioSessionManager 提取到 apps/mobile/src/components/ 或独立 media 共享模块，从根上满足 §2.2。
  3. 补齐核心纯逻辑测试：优先为 trail-creation、reflectionGraph、reflectionAnalytics 写单测，把覆盖率拉到 ≥80%，兑现 P5。
  4. 收敛超大 app 文件：按 §4.1 软上限逐项拆分（HomeScreen、db/schema、PlanDetailContent 等），将可测试规则逐步回流到 core。
  5. 澄清后端认证模型：确认 users 集合归属并在 schema 或文档中显式标注，避免部署歧义。
  6. 校准"薄壳"定位：将 Sync/Sleep/Breathing 等引擎的纯逻辑下沉到 core，app 层仅保留 UI / 动画 / 平台副作用，使 P1/P2 从愿景变为事实。

八、总体结论

架构的骨架是健康的：单向依赖 app → core 被严格守住，core 确实集中了类型 / 常量 / 纯函数 / 同步协议，PocketBase 作为唯一数据源的设计自洽。但宪法文本已严重落后于实现——它既误置了 _archive 路径、又用过期且自相矛盾的行数表描述现状，同时最大的引擎类仍躺在 app 层，使"core = Sole Source of Truth"更像目标而非现状。

最值得立刻动手的真实缺陷是 5 处跨 feature 非法 import 与 core 大文件测试缺位；而校准宪法文档是让后续所有重构有据可依的前提。技术债整体可控，不属于需要推倒重来的范畴。
